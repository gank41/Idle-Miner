# Building Idle Miner

## Apple Silicon Mac

Use an Apple Silicon Mac with macOS 14 or later and the Xcode command-line tools.
Clone the repository, open Terminal in its folder, then run:

```sh
zsh build.sh
```

This creates `Idle Miner.app` in the repository folder. The build uses the included
unmodified XMRig 6.26.0 Apple Silicon engine and its license, and compiles the
native Swift controller and C supervisor. It signs the app locally for development;
it does not notarize it or create a Developer ID release. It does not install,
launch, or start mining. Copy the app to Applications when ready. Quit all installed
currency instances before replacing an installed app. Wallets and runtime settings
live outside the repository and are not bundled.

The corresponding XMRig upstream source is included in
`Linux/vendor/xmrig-6.26.0.tar.gz`; the macOS binary is in
`macOS/Resources/xmrig`. See the [upstream build instructions](https://xmrig.com/docs/miner/build).
The mining algorithm/provider config is generated by `Sources/Core.swift`.

For native Mac regression checks:

```sh
zsh test.sh
```

These checks open isolated test windows and run brief offline engine work. Their
settings are temporary, and offline engine checks earn nothing and connect to no
pool. Some checks require permission to inspect their own child processes. They
neither change the installed app nor use your saved wallet. Only the app's ordinary
Start command or an explicit `--start-mining` launch enables online mining.

## Linux

On a supported desktop distribution, open Terminal in `Linux` and run:

```sh
bash install.sh
```

The installer builds pinned XMRig source, its supervisor and the desktop idle helper
for the local 64-bit architecture. It uses the normal package manager for missing
dependencies. Run as your desktop user; sudo is used only for dependencies.
See [Linux README](Linux/README.txt) for prerequisites and installed paths.

## Release packages

Prebuilt Mac disk images and Linux source installers are published as GitHub
Release assets, rather than stored in Git history. Each release includes SHA-256
checksums and a corresponding source snapshot. The source snapshot must include
the same native/Python controller, supervisor, resources and pinned upstream
engine source as the downloadable release. Public packages must contain no wallets,
settings, logs, account balances, developer credentials or private audit records.
