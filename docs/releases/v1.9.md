# Idle Miner 1.9 (build 12)

## Built-in updates

Choose **Check for Updates…** to see the installed version, latest version, and plain-text release notes inside the app. Choose **Close** or **Download and Install Now**. Checks run only on request; there are no background checks or unattended installations. Wallet addresses and mining settings are not sent with update requests.

Mac uses Sparkle 2.10.1 with a signed appcast and signed disk image. Choosing **Download and Install Now** stops matching currency instances and their engines before downloading and keeps mining stopped throughout the update. The disk image signature is verified before extraction, the actual app location is replaced, and the app reopens stopped. **Close** before choosing installation leaves mining unchanged; canceling afterward leaves mining stopped. Sparkle can request administrator authorization when required by the existing location's permissions.

Linux authenticates the signed manifest and archive, builds a staged replacement first, then replaces the existing application directory while preserving its launcher. A failed replacement rolls back. The updater does not run hidden sudo commands; missing dependencies or unwritable locations are reported before installation. The app reopens stopped. Both platforms preserve saved wallets and settings.

**Version 1.8 and earlier require one manual installation of 1.9.** Quit every currency instance, then use the [installation guide](https://idleminer.app/guide.html). The old updater cannot install the new update mechanism by itself. Original 1.8 download URLs remain available with their original bytes.

## Mac signing and Apple notarization

The Mac app is Developer ID signed with hardened runtime. Apple accepted notarization for build 12, and its ticket is stapled to the app. Local Gatekeeper assessment passed. Update signatures, Developer ID signing, and Apple notarization are separate checks; the statement here applies to the app inside the disk image.

## Verification limits

The Mac app passed Developer ID signature verification, Apple notarization, stapled-ticket validation and local Gatekeeper assessment.

- Mac native regressions passed: 59 core checks, 53 stats checks, 70 legacy update-format assertions, engine reload/supervisor cleanup, settings/login, Ethereum, shared CPU and four-process menu tests. New updater policy and native UI tests passed. Test controllers use a controlled healthy sensor fixture; production retains the actual battery, thermal, sleep and memory checks.
- Real Sparkle installations passed from an arbitrary writable folder containing spaces. Signed ZIP and DMG fixtures replaced build 1 with build 2 at the same path and relaunched. Tampered ZIP and DMG payloads were rejected with the original app retained. The fixtures used actual embedded Sparkle, peer shutdown and worker leases, and preserved the external fake-wallet file. Only loopback test requests were made; no real wallet or mining pool was used.
- The Developer ID hardened-runtime engine passed the offline 1→2→1 thread reload test with its JIT entitlement.
- All 68 Linux tests passed on Fedora 44 ARM64 with a fresh native engine/helper/supervisor build. Coverage includes manifest/archive authentication, cancellation, safe extraction, custom paths, transaction rollback, engine leases and stopped relaunch.
- All 15 deployment/feed fixtures passed, including signed-feed authentication, tampered-payload rejection and immutable 1.8 download retention.

Final packages are checked for source parity, SHA-256 hashes, signed-feed/archive verification, private-content exclusion, Mac version/signature, mounted icon and drag-to-Applications layout before publication. The public feed is not populated with fake future releases for testing.

Protected/read-only target permissions, native administrator authorization and an actual operating-system logout/login remain manual coverage gaps. Native Asahi hardware operation remains unverified. The app must first be copied off its installer disk image to a writable install location.
